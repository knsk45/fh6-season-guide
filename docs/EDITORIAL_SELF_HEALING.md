# Самолечение редакторских ошибок

24.10.2026 по снимку владельца проверен ручной запуск
`fh6-20261022-142804-734179`. Его portable-журнал с подтверждённым SHA содержит:
`English locale is missing howHtml for activity_01_weekly`.
Ошибка Node находилась внутри renderer, а не в проверке receipt издателя.
Старое правило диагностики ошибочно относило любой `PORTABLE_*FAILED` к receipt
и теряло конкретную причину. Авторазбору не хватало данных для исправления.

К 24 октября текущая английская версия уже исправна и дневная сборка прошла.
Исторический запрос не переписывается и повторно не публикуется. Панель выводит
текущий запуск первым; прежние запросы сохраняются в раскрываемой истории.

## Что исправляет сборщик

До принятия редакторского результата `editorial_health.validate_locale` проверяет
тот же контракт, что renderer: reportTitle, seasonDisplay, каждый activity id и
непустые title/points/conditionHtml/howHtml/tuneHtml для каждой карточки.
Пропуск возвращается в существующий цикл редактора с конкретным полем и id.
Редактор получает до трёх ограниченных попыток в той же изолированной копии.
Перевод делается из подтверждённых русских данных с сохранением годов машин,
кодов, ограничений и статуса неизвестных сведений. Додумывать решения запрещено.
Пока проверка не пройдена, канонические данные и публикация не меняются.

Если такой сбой всё же записан на этапе portable/html/structure/audit,
существующий recovery распознаёт `LOCALIZATION_INCOMPLETE` по фиксированному
формату ошибки. Журнал этапа должен находиться в каталоге этого run и совпадать
с записанным SHA; произвольные или изменённые журналы не дают права на ремонт.
Повтор направляется редактору для свежего полного аудита, а не в быструю
пересборку того же ошибочного состояния. Остаются общие задержки 5/15/60 минут
и максимум три попытки recovery за серверные сутки. Исторические дни не
переигрываются. Неполный аудит после трёх редакторских попыток остаётся
NEEDS_REVIEW; неизвестные ошибки структуры не превращаются в слепые повторы.

Существующее восстановление временных сетевых сбоев и подтверждённого повторного
входа сохраняется. Исследование плиток учитывается как занятой сборщик; все
пути используют единую runner.lock. Самолечение не устанавливает произвольные
предложенные моделью изменения кода, не меняет секреты, согласия или валидаторы.
Новые данные проходят полный обычный guard, сборку, проверки и публикацию CT109.

## Диагностика и проверки

В очищенную диагностику включаются только фиксированный код проблемы, имя
поля из разрешённого списка и ограниченный activity id. Сырые команды,
исключения, URL с авторизацией и журналы не копируются в панель/модельный отчёт.
Подробный PORTABLE_BUILD_FAILED больше не маскируется под ошибку receipt.

Пройдено 152 server unittest cases, 30 guard tests, 21 portable tests;
браузерные сценарии панели 390/1440 и диагностики. Регрессии проверяют пустые
и неверные типы всех английских полей, ранний отказ до принятия, ограниченный
повтор, выбор редакторского пути вместо повторной сборки, отсутствие ремонта
старых дней, защиту диагностических полей и сохранение старой ошибки в истории.

На CT109 изменены runner.py, recovery.py, incident_reports.py, phone_view.py,
diagnose.py; добавлены editorial_health.py и test_editorial_health.py. Установка
выполнена под общей блокировкой после штатного завершения поиска плиток.
Backup/manifest/candidate: `/var/lib/fh6/maintenance/self-healing-20261024/`.
Перезапущена только fh6-phone.service; таймеры и включённый поиск сохранены.
Живые проверки: валидная текущая локализация, верный диагноз старого запуска,
текущий результат перед архивом, поиск enabled=true, failed units=0.
Первый поиск завершился NO_NEW_TILES; он не был прерван этой установкой.
Реальный новый сбой локализации намеренно не создавался: самолечение проверено
изолированными сценариями, а не порчей рабочего сезона.

Откат при свободной runner.lock: восстановить пять прежних файлов из
`backup/automation/server/`, перезапустить fh6-phone.service. Новые helper/test
можно сохранить неактивными. Данные сезона, старая история и tile-search.json
этой установкой не изменялись. Полноценный откат установки не выполнялся.
