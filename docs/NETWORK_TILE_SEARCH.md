# Поиск игровых плиток без ноутбука

В панели сборщика, в разделе **Игровые скриншоты**, включите
**Искать плитки в сети**. Настройка хранится на CT109 и переживает перезапуск.
Первая попытка начинается в течение минуты, последующие — раз в три часа.
Статус, последняя и следующая попытки, число недостающих плиток видны рядом.
Изначально настройка выключена. Пока все плитки найдены, модель не вызывается;
после появления новых пробелов поиск продолжится при следующей проверке.

Поиск выполняет существующий изолированный серверный редактор с сетевым поиском.
Он проверяет источники и реальные пиксели, сохраняет оригинал, точный кадр,
URL и запись в SOURCE_NOTES. Принимаются только полные игровые плитки текущей
недели. Daily остаётся текстовым. Существующие плитки, включая месячные, сохраняются.
Факты сезона, тексты, переводы и даты поисковая попытка менять не может.

Новые плитки проходят обычный полный аудит, проверку структуры и guard на CT109.
Издатель остаётся единственным. Без новых плиток сводка повторно не публикуется
и итоговое HA-уведомление не отправляется. Обычные ежедневные проверки сохраняются.
Если сборщик занят или ждёт восстановления/доставки, поиск уступает ему очередь.
Вход в Codex при необходимости выполняется через существующий раздел панели.

Выключение тумблера останавливает редакторский поиск (проверка отмены каждые
пять секунд во время работы модели; текущий сетевой сбор имеет свой таймаут).
Уже начатая проверенная публикация заканчивается штатно, чтобы не оборвать
сборку или доставку. Повторное включение разрешает новую попытку без ожидания
старого трёхчасового интервала. Настройка не даёт дополнительного согласия Steam.

## Установка и проверка

Код: `automation/server/tile_search.py`, интеграции в `runner.py`, `phone_ui.py`,
`phone_view.py`. Root worker: `fh6-tile-search.service`; timer проверяет настройку
раз в минуту, сама политика ограничивает исследование интервалом в три часа.
Используется общая неблокирующая `runner.lock`, отдельный publisher не создаётся.
Настройка `/var/lib/fh6/tile-search.json` отделена от worker-owned
`tile-search-status.json`. Отсутствующая настройка означает выключенный поиск.
Публичные ответы содержат только фиксированные статусы и числа, без сырых логов.
POST `/tile-search` использует существующую авторизацию и защиту Origin/CSRF.

После адресного резервирования и установки исходников:

```sh
install -m 0644 automation/server/fh6-tile-search.service automation/server/fh6-tile-search.timer /etc/systemd/system/
systemctl daemon-reload
systemctl restart fh6-phone.service
systemctl enable --now fh6-tile-search.timer
```

24.10.2026: установлено на CT109 с проверкой исходных SHA; backup и manifest:
`/var/lib/fh6/maintenance/tile-search-20261024/`. Тумблер оставлен выключенным.
Проверены 142 серверных теста до дополнительного теста успешной публикации,
затем все 11 тестов tile search, 30 guard tests и браузерные сценарии панели
390/1440 и диагностики. Проверены живой HTML/JSON панели, успешный пустой запуск
выключенного worker, активный timer, отсутствие failed units. Реальное фоновое
исследование начнётся после включения; найденных новых плиток при установке нет.

Откат при свободном сборщике: выключить/остановить `fh6-tile-search.timer` и
его service, восстановить изменённые `runner.py`, `phone_ui.py`, `phone_view.py`
и два прежних теста из `backup/automation/server/`, перезапустить только
`fh6-phone.service`. Новые исходники можно сохранить неактивными для аудита.
Сезонные данные и прежние таймеры откат этой установки не затрагивает.
