# FH6 на Proxmox

Первый этап — гибридный: технический конвейер работает в CT109, редакторские
аудиты можно готовить в чате или через отдельный серверный Codex CLI после
входа владельца. Новый сезон требует редакторской проверки; никакой сезон
не создаётся по календарной догадке. Полной автономностью такой режим до
входа в Codex и проверки реального аудита не считается.

## Размещение

- Unprivileged Debian 13 LXC, 2 vCPU, 2048 MiB RAM, 512 MiB swap, 32 GiB диск.
- `/opt/fh6/repo`: ветка `daily-season`, публикация через guard, без force-push.
- `fh6`: издатель; GitHub SSH deploy key имеет доступ только к этому репозиторию.
- `fh6-editor`: отдельный пользователь без ключа GitHub и секрета HA. Изолированная
  рабочая копия не содержит `.git`, ignored runs, прежние токены и серверные секреты.
- `/etc/fh6/home-assistant.json`: только используемый проектом токен, режим 0600.
- `/var/lib/fh6`: снимки доступности, очередь оригиналов, подтверждения, журналы.
- Chromium + Playwright: реальная проверка загрузки/декодирования каждого локального
  изображения; скриншот сам по себе не доказывает доставку или правильность фактов.

Редактор не публикует и не имеет авторизованного Steam. Он исследует живые
источники, готовит state/SOURCE_NOTES/audit. Supervisor принимает только
структурно валидный свежий полный аудит. HTTP 200, хеш старой картинки или
наличие слова Summer не заменяют исследование источника и визуала.

## Телефон

Закрытая страница `https://192.168.1.55:8443/` доступна только в домашней сети
или существующем VPN. Интернет-порты/роутер/публичный прокси не изменяются.
TLS-сертификат локальный самоподписанный: SHA256 надо сверить с уведомлением
на телефоне. Персональный пароль передаётся только напрямую через HA; он не
появляется в Git или чате. Это отдельное установочное сообщение, не итог
ежедневного запуска и не событие watchdog.

Страница показывает итог и позволяет:

- загружать оригинальные PNG/JPEG/WebP без преобразования; имя UUID, SHA-256 receipt;
- прочитать обе версии Steam и подтвердить конкретный общий SHA текста;
- запросить `codex login --device-auth` и увидеть код только в закрытой странице.
- запустить внеплановую проверку без включения ПК; незавершённая попытка возобновляется.

### Пароль владельца при первом входе

Логин панели — `knsk45`. Владелец устанавливает собственный пароль через
одноразовое приглашение Home Assistant «FH6 — установите свой пароль».
Приглашение действует 24 часа; после успешного сохранения оно недействительно.
Без приглашения `/setup` возвращает 404, остальная панель по-прежнему требует
Basic auth. Пароль вводится дважды, ограничений длины/сложности нет; пустой
пароль, перевод строки и NUL не принимаются. Открытый текст не
пишется в файлы, журналы или чат. Корневой Unix-socket broker принимает только
SHA-512 crypt hash и подтверждённое приглашение, не предоставляет shell/API
для других действий. Изоляция веб-службы (`NoNewPrivileges`, `ProtectSystem`)
сохраняется. Конфигурация брокера root-owned; старый hash сохранён в root-only
recovery-файле. Автоматический повторный запуск не сбрасывает пароль.
Каталог `/etc/fh6` остаётся `root:fh6`, 0750; адресный ACL даёт `www-data`
только проход (`--x`) к `phone.htpasswd` (`root:www-data`, 0640), без доступа
к HA, приватному TLS-ключу или состоянию приглашения. Не добавлять nginx
в группу `fh6`. Preflight проверяет чтение файла именно пользователем nginx
и HTTP 401 с заведомо неверными тестовыми credentials: простой запрос без
Authorization не выявляет ошибку доступа, возникающую только после ввода пароля.

Для первоначального приглашения администратор CT109 выполняет один раз:
`python3 /usr/local/lib/fh6/phone_password.py prepare`. Токен и ссылка
передаются напрямую телефону, stdout содержит только статус принятия HA.

Код вводит сам владелец в официальном входе; по окончании/таймауте временный
вывод удаляется. Токены входа остаются в приватном home редактора. Не отправляйте
пароль, код или auth.json в чат. Порядок входа описан в
[официальной документации](https://learn.chatgpt.com/docs/auth).

Подтверждение Steam здесь — разрешение, НЕ отметка публикации. До автоматизации
авторизованного редактора Steam владелец заменяет ровно две существующие секции
через Steam браузер телефона. Только после публичной проверки обеих секций
можно запускать mark/check. Неподтверждённый текст остаётся pending.

## Расписание и восстановление

`fh6-refresh.timer` запускает сервер ежедневно в 06:00 Asia/Krasnoyarsk.
`fh6-preflight.timer`: четверг 20:30, только preflight без публикации.
Независимый watchdog HA в 06:30 не изменяется и не отключается.
Доставка сохранённого итога повторяется каждые пять минут отдельным timer,
без повторной сборки, нового аудита и дублирования уже подтверждённого уведомления.
Windows task и heartbeat следует отключать только после серверных проверок.
Нельзя держать двух независимых издателей. Чат может исследовать/подготовить
аудит, но исполняет его в серверном guard, а не локально на ПК.

Неудачная доставка остаётся AWAITING_DELIVERY. Повторный запуск supervisor
возобновляет её; подготовленный отчёт не пересобирается. Для старой, никогда
не доставленной попытки после смены дня `close-expired` сохраняет исходный
result byte-identically и создаёт честный CheckBlocked. Только после отправки
и authenticated receipt она закрывается; старый успех не считается сегодняшним.

Проверки:

```sh
cd /opt/fh6/repo
python3 automation/test_portable_report.py
python3 automation/test_refresh_guard.py
python3 automation/server/test_server.py
/opt/fh6/venv/bin/python automation/server/browser_qa.py \
  https://knsk45.github.io/fh6-season-guide/reports/current-week.html \
  /var/lib/fh6/public-qa.png
```

Для ручного аудита после синхронизации canonical state/assets/SOURCE_NOTES:

```sh
python3 automation/server/runner.py publish-audit --audit /path/to/audit.json
```

Хеши базовых снимков Steam/метрик сохраняются при переносе; исходный журнал
Windows сохраняется отдельно. Абсолютные пути переносятся только в checkpoint,
первичные журналы/result/archive остаются доказательствами. Старый portable
receipt не становится Linux receipt простым переписыванием путей: его создаёт
следующая настоящая сборка.

## Отказ и откат

Остановка: `systemctl stop fh6-refresh.timer fh6-preflight.timer`. Старую задачу
ПК включать только после остановки серверного publisher и проверки canonical
state/метрик/Steam baseline. Оригинальные плитки, месячные assets, history и
seasons не удаляются. CT109 входит в существующий weekly backup job `all=1`;
для завершения внедрения нужен отдельный проверенный исходный vzdump.
Нельзя считать включённое расписание доказательством успешного backup/restore.
