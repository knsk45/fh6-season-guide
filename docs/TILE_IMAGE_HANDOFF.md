# Передача исходных изображений сетевому поиску

24.10.2026 установлена причина, почему первый поиск не принёс плиток:
редактор получал ссылки через web search, но его workspace-write sandbox не
разрешает прямую сетевую загрузку. Web tool также возвращал Cache miss для
изображений CDN. HTTP 200 к странице источника не давал редактору пикселей.
Тот же оригинальный PNG успешно загружался штатной сетью CT109 вне редактора.
Поэтому старое NO_NEW_TILES смешивало отсутствие подтверждённых материалов с
невозможностью их получить. Это был пропуск в организации загрузки.

`automation/server/tile_images.py` выполняет ограниченную загрузку до запуска
редактора, аналогично уже существующему сбору source-snapshots. Сетевая изоляция
редактора сохраняется. Разрешены только фиксированная страница ForzaLabs и
её CDN `cdn.sanity.io/images/jr6fd40q/production/`. Произвольные адреса,
перенаправления, SVG/HTML и неизвестные пути не принимаются. Есть лимиты
числа файлов, байтов и времени. Параметры CDN преобразования удаляются:
сохраняются оригинальные байты, SHA-256, подпись и исходный URL.

Из HTML выбирается только article с точным id `<season>-<startAt date>` из
канонического состояния. Другие недели не используются. Если текущего
раздела нет, никакая соседняя дата или сезон автоматически не подставляется.
Эти файлы остаются кандидатами: подпись, успешная загрузка и hash не означают
визуальной проверки. До рабочего состояния и публикации они сами не доходят.

Кэш `/var/lib/fh6/tile-image-cache/<section>/` с index.json копируется в
изолированную рабочую папку редактора как `network-tile-candidates/`. Редактор
должен открыть действительные локальные изображения, проверить активность,
полноту и неделю, сохранить принятый оригинал byte-for-byte, подготовить точный
кадр и записать provenance в SOURCE_NOTES. Daily остаётся текстовым, известные
плитки и Monthly сохраняются. Дальше действует прежний полный audit/guard,
проверка кандидата и единственный publisher CT109.

В панели показывается число полученных изображений **для проверки**, отдельно
от числа недостающих плиток. При недоступных байтах состояние теперь
SOURCE_UNAVAILABLE, а не NO_NEW_TILES. Бесконтрольных повторов или второго
publisher нет. Период поиска и включённое согласие владельца не меняются.

Проверки:158 server unittest cases, мобильный/desktop browser сценарий панели
и incident browser. Изолированные тесты проверяют точный раздел недели,
отказ от чужих origins/портов/traversal, byte-exact исходники, отбрасывание
HTML вместо изображения, честный статус неудачной загрузки. Живой сервер
получил 20 изображений, включая основные плитки 11 отсутствовавших активностей;
один дополнительный материал не загрузился. Два оригинала дополнительно
открыты локально для визуальной проверки. Принятие и публикация всех плиток
подтверждаются отдельно результатом запуска, а не самим этим счётчиком.

Backup/candidate/manifest установки:
`/var/lib/fh6/maintenance/image-handoff-20261024/`. Изменены runner.py,
tile_search.py, phone_view.py; добавлены tile_images.py и test_tile_images.py.
Установка выполнена с проверкой исходных SHA под общей runner.lock.
Перезапущена только панель. Для досрочной повторной проверки сохранён прежний
tile-search-status.json, его cooldown сброшен один раз, затем запущен существующий
fh6-tile-search.service. Policy version и enabled=true сохранены.

Откат при свободном сборщике: восстановить три прежних файла из backup,
перезапустить fh6-phone.service. Кэш исходников можно сохранить для аудита.
Принятые позднее сезонные данные требуют отдельной адресной проверки/отката;
откат загрузчика не должен терять опубликованные оригиналы.

## Повторное использование проверенных оригиналов

Дополнительная проверка выявила ещё один случай: после успешной первичной
загрузки #PolarisPoint временный сбой повторного запроса убирал эту строку из
нового index.json, хотя её правильный raw уже лежал в кэше. Теперь каждый URL
имеет отдельный source-receipt. Перед повторным использованием проверяются
URL текущего раздела, разрешённый basename, размер и SHA-256 фактических байтов.
Изменённый файл не принимается; исходник загружается снова. Временная ошибка
загрузки получает один ограниченный повтор. Новая проверка source page нужна
всегда: наличие старого файла само по себе не подтверждает текущую неделю.

Пройдено 160 server tests, включая reuse при временном сбое и отказ от
повреждённого кэша. Backup этой доработки:
`/var/lib/fh6/maintenance/image-cache-retry-20261024/`. Изменены только загрузчик
и его тест; перезапуски/настройки служб не понадобились. Ранее успешно полученный
original Polaris восстановлен в source-receipt по известным URL и SHA (1519701
байт, `a5b7351b1cf0c3e0d8acff17f50a89c5c9f64630aa3b17b2a963a3e9bc330d10`),
дополнительно открыт локально и передан следующей изолированной попытке.
